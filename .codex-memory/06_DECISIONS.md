# Decisions

## 2026-05-08 Centralized Settings

Контекст: настройки не должны задаваться вручную на каждом телефоне сотрудника.

Решение: настройки хранятся централизованно в Google Sheets / Apps Script и подтягиваются формой при старте, при возврате вкладки в фокус и раз в 6 часов.

Альтернативы: localStorage на каждом устройстве; хардкод в `index.html`; отдельная база данных.

Последствия: руководитель меняет настройки один раз, все сотрудники получают обновления; нужно аккуратно разделять публичные настройки и секреты.

## 2026-05-08 Telegram Secrets Server-Side

Контекст: репозиторий публичный, Telegram Bot Token нельзя держать в браузере.

Решение: секреты Telegram должны жить в Apps Script `PropertiesService`; Apps Script отправляет сообщения и фото.

Альтернативы: отправка напрямую из `index.html`; хранение токена в localStorage; хранение токена в GitHub repo.

Последствия: безопаснее для публичной формы; нужно убрать оставшийся legacy client-side Telegram code.

## 2026-05-08 GitHub Pages And Custom Domain

Контекст: форма должна открываться простой ссылкой с телефона.

Решение: публиковать `main` через GitHub Pages, использовать кастомный домен `no-money-no-honey.ru`.

Альтернативы: Netlify; Apps Script HTML as frontend; локальный HTML.

Последствия: простой deploy через GitHub; повышенные требования к секретам из-за публичности repo.

## 2026-05-08 Native Calendar

Контекст: календарь не срабатывал стабильно; пользователь спрашивал, можно ли менять дизайн календаря.

Решение: использовать системный `input[type=date]`, не писать кастомный календарь.

Альтернативы: кастомный календарь на JS; UI-library.

Последствия: меньше кода и выше мобильная надёжность; дизайн календаря контролируется устройством, а не приложением.

## 2026-05-08 Remove +/- 3 Day Limit

Контекст: руководителю нужно внести данные начиная с 1 мая, но сотрудники не должны свободно менять давние смены.

Решение: снять ограничение `±3 дня`, но блокировать даты старше 2 дней для обычного сотрудника.

Альтернативы: оставить `±3 дня`; разрешить всем любые даты; внедрить полноценные роли и аудит.

Последствия: проще внести историю, но старые даты защищены от обычного сотрудника.

## 2026-05-08 Owner Retro Entry

Контекст: ретроввод должен быть доступен руководителю, но в отчёте должен стоять реальный сотрудник смены.

Решение: при старой дате показывать fullscreen blocker, после PIN руководителя открыть выбор сотрудника.

Альтернативы: ручной ввод в таблицу; отдельный админский сайт; роли и логирование.

Последствия: исторические смены лучше вносить через форму; логирование действий руководителя пока не нужно.

## 2026-05-08 Apps Script Deployment By User

Контекст: Apps Script deployment создаётся вручную, URL может меняться, старые deployments кэшируются.

Решение: Codex правит `Code.gs`, пользователь создаёт новое deployment и присылает URL, Codex обновляет `index.html` и пушит.

Альтернативы: Codex пытается деплоить сам; редактировать существующий deployment.

Последствия: меньше путаницы с кэшем Apps Script, но нужен явный handoff после backend-правок.

## 2026-05-08 Project Memory

Контекст: пользователь хочет открывать новый диалог Codex и продолжать без потери контекста.

Решение: создать `.codex-memory/` с numbered markdown files.

Альтернативы: держать контекст только в чате; расширять только README.

Последствия: новый Codex должен читать файлы по номерам; папка не добавляется в `.gitignore`, пока пользователь не скажет, что память локальная.
